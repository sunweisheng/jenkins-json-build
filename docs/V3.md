# Jenkins Json Build V3

V3 的核心是通用阶段和步骤注册机制。`v3.2.0` 在保持 V2.1 和现有 Java 行为兼容的基础上，增加 Node、Android、React Native、iOS 和旧版 .NET Framework 构建能力。

## 支持范围

正式步骤：

- `command`、`condition`、`retry`、`timeout`、`setVariable`
- `credentials`、`archive`
- `maven`、`npm`、`gradle`、`msbuild`
- `junit`、`jacoco`、`coverage`、`sonarqube`
- `xcodebuild`、`xcodeCoverage`、`appleSigning`
- `containerImage`，默认 builder 为 `buildkit`，兼容 `kaniko`
- `helm`，支持 `lint`、`template`、`upgrade`、`status`、`rollback`

正式模板：

- Java：`java-maven-static`、`java-maven-kubernetes`、`java-maven-kubernetes-kaniko`
- Node：`node-npm-static`、`node-npm-kubernetes`
- Android：`android-gradle-static`、`android-gradle-kubernetes`
- React Native Android：`react-native-android-static`、`react-native-android-kubernetes`
- iOS：`ios-xcode-static`、`react-native-ios-static`
- 旧版 .NET Framework：`dotnet-framework-msbuild-windows`

iOS 只使用 Mac Agent；旧版 .NET Framework 只使用 Windows Agent。V3.2.0 不增加现代 `dotnet` 步骤。V2 项目可继续使用 `v2.1`，也可先运行转换工具生成报告。

## 配置入口

```groovy
@Library('jenkins-json-build@v3.2.0') _

jenkinsJsonBuild(
    configFiles: ['ci/base.json', 'ci/service.json'],
    onlyStages: ['test', 'package'],
    projectIds: ['api'],
    callbacks: [
        success: { context, error -> echo "${context.projectId} success" },
        failure: { context, error -> echo "${context.projectId} failed" }
    ],
    stepHandlers: [
        'company.customStep': { context, config ->
            echo config.message
        }
    ]
)
```

默认使用 Jenkins 提供的 `scm` 检出源码。内联 Pipeline 或验收任务可通过 `jenkinsJsonBuild(scm: [...])` 显式传入 Jenkins SCM 配置。

每次调用都会创建新的执行对象。不同 Jenkins 构建和不同项目不共享当前阶段、变量或结果。
`configFiles` 会按填写顺序合并为一份配置，后面的变量和普通字段覆盖前面的值，同编号阶段在原位置合并。

## JSON 结构

```json
{
  "schemaVersion": 3,
  "project": {"id": "example"},
  "variables": {"JAVA_VERSION": "21"},
  "runtimeVariables": [
    {"name": "SHORT_SHA", "source": "command", "script": "git rev-parse --short=12 HEAD"}
  ],
  "parameters": [
    {"name": "DEPLOY", "type": "boolean", "defaultValue": false}
  ],
  "agent": {"type": "static", "label": "linux"},
  "stages": [
    {
      "id": "test",
      "name": "Test",
      "timeoutMinutes": 30,
      "retries": 1,
      "condition": {"variable": "DEPLOY", "operator": "equals", "value": true},
      "variables": {},
      "steps": [
        {"type": "maven", "goals": ["clean", "test"]},
        {"type": "junit", "testResults": "**/target/surefire-reports/TEST-*.xml"}
      ]
    }
  ],
  "post": {
    "success": [],
    "failure": [],
    "cancelled": [],
    "always": []
  }
}
```

变量从低到高依次为 Jenkins 环境和参数、全局变量、运行时变量、项目变量、阶段变量、步骤变量。后面的同名变量覆盖前面的值。未解析的 `${NAME}` 会直接停止构建。

运行时变量支持 `env`、`parameter`、`command`、`file`、`http` 和 `json`。HTTP 地址必须是 HTTPS，主机必须放入 `trustedHosts`。HTTP 读取默认 30 秒超时；入口可用 `httpTimeoutSeconds` 调整，单个 HTTP 运行时变量可用 `timeoutSeconds` 覆盖。Credentials 只能通过 `credentials` 步骤临时绑定；凭据值不会进入普通变量和构建结果。命令内直接使用 Jenkins 绑定的 `$PASSWORD` 一类 shell 环境变量，不要写成 V3 的 `${PASSWORD}`。

## 构建参数

V3.2.0 支持 `string`、`boolean`、`choice`、`agentServer` 和 `customCheckbox`。旧配置 `multiChoice + provider: customCheckbox` 继续有效。

```json
{
  "parameters": [
    {"name": "BRANCH", "type": "string", "defaultValue": "main"},
    {"name": "DEPLOY", "type": "boolean", "defaultValue": false},
    {"name": "MODE", "type": "choice", "choices": ["test", "release"]},
    {"name": "BUILD_AGENT", "type": "agentServer", "defaultValue": "mac-m2-16g"},
    {
      "name": "PROJECTS",
      "type": "customCheckbox",
      "format": "YAML",
      "pipelineSubmitContent": "projects:\n  - name: iOS\n    id: ios\n    checked: true\n",
      "displayNodePath": "//projects/name",
      "valueNodePath": "//projects/id",
      "checkedNodePath": "//projects/checked"
    }
  ]
}
```

Custom Checkbox 支持内嵌 JSON/YAML，也支持 `HTTP_HTTPS` 和 `FILE_PATH`。`pipelineSubmitContent` 与 `uri` 必须且只能设置一个。FILE_PATH 必须填写 Jenkins Controller 能读取的绝对路径，例如 `/var/jenkins_home/project-list.yaml`；插件不会展开 `$JENKINS_HOME`。HTTP_HTTPS 由插件从 Controller 发起请求，同时支持 HTTP 和 HTTPS。

历史选择会成为下一次默认值。历史值为空字符串表示用户明确全部取消，不会重新采用文档中的 `checked: true`。只有存在历史值或配置显式提供 `defaultValue` 时，共享类库才覆盖文档中的初始勾选。

首次创建参数或以后新增参数时，本次构建标记为 `NOT_BUILT`，不分配 Agent、不检出源码；重新进入 Build with Parameters 后再执行。项目选择参数存在但全部取消时会停止，空值不会被解释为构建全部项目；未知项目编号同样会被拒绝。

`agentServer` 由 Agent Server Parameter 插件提供，列表保留 Jenkins 当前全部节点，当前选择作为下一次默认值。

## 静态 Agent 检查

静态 Agent 可在 `requirements` 中声明系统、CPU 架构和工具。检查发生在源码检出前。

```json
{
  "agent": {
    "type": "static",
    "label": "macos ios",
    "requirements": {
      "os": "macos",
      "architectures": ["arm64"],
      "tools": ["node", "xcodebuild", "xcrun"]
    }
  }
}
```

`os` 支持 `linux`、`macos`、`windows`。Windows 使用 `PROCESSOR_ARCHITECTURE` 和 `Get-Command` 检查，Linux/macOS 使用 `uname` 和 `command -v` 检查。工具版本仍由模板、项目变量和节点安装基线管理。

## 多语言步骤

`npm`、`gradle` 和 `msbuild` 使用结构化参数生成对应平台的命令：

```json
{"type": "npm", "executable": "npm", "command": "ci", "workDir": "web"}
```

```json
{"type": "gradle", "executable": "./gradlew", "tasks": ["test", "assembleDebug"], "arguments": ["--no-daemon"], "workDir": "android"}
```

```json
{"type": "msbuild", "executable": "MSBuild.exe", "project": "App.sln", "targets": ["Build"], "properties": {"Configuration": "Release", "Platform": "Any CPU"}}
```

三种步骤都支持 `workDir`、`environment`、`arguments` 和 `artifacts`。MSBuild 只面向旧版 .NET Framework/Visual Studio Build Tools，不调用现代 `dotnet`。

`coverage` 封装 Coverage 插件的 `recordCoverage`：

```json
{
  "type": "coverage",
  "reports": [
    {"format": "LCOV", "pattern": "coverage/lcov.info"},
    {"format": "JACOCO", "pattern": "**/jacocoTestReport.xml"}
  ],
  "qualityGates": [
    {"metric": "LINE", "baseline": "PROJECT", "threshold": 80, "unstable": false}
  ],
  "sourceCodeRetention": "LAST_BUILD"
}
```

报告格式支持 `COBERTURA`、`JACOCO`、`LCOV`、`OPENCOVER`。质量门槛等 Coverage 插件参数原样传给 `recordCoverage`。

非 Maven 项目的 SonarQube 使用 `script`、`shell`、`workDir` 和 `environment`；未设置 `script` 时继续使用原有 Maven 方式。

## iOS 构建与签名

`xcodebuild` 支持 `clean`、`build`、`test`、`archive`、`exportArchive`，可设置 workspace/project、scheme、configuration、destination、DerivedData、xcresult、Archive、ExportOptions 和 IPA 输出。

```json
{
  "type": "xcodebuild",
  "action": "test",
  "workspace": "App.xcworkspace",
  "scheme": "App",
  "destination": "platform=iOS Simulator,name=iPhone 17 Pro,OS=latest",
  "resultBundlePath": "build/AppTests.xcresult",
  "enableCodeCoverage": true
}
```

`xcodeCoverage` 调用 `xcrun xccov` 读取 xcresult 汇总，再生成 Cobertura XML 交给 Coverage 插件。xccov 汇总只提供每个文件的可执行行数和覆盖行数，因此生成的 Cobertura 行号用于表达汇总比例，不代表源码中的真实行位置。

`appleSigning` 接收 P12 文件凭据、P12 密码文本凭据和一个或多个 provisioning profile 文件凭据。它创建独立临时钥匙串，只把新描述文件复制到当前用户目录；成功、失败或取消时都会恢复原钥匙串列表，并删除临时钥匙串、临时状态目录和本次新增的描述文件。详细配置见 [凭据说明](CREDENTIALS.md)。

Mac 节点准备和 SSH Launcher 配置见 [Mac Agent 安装说明](MAC_AGENT.md)。

## Java 模板

静态 Agent：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-static",
  "project": {"id": "java-service"},
  "variables": {"ENABLE_SONAR": false}
}
```

Kubernetes + rootless BuildKit + Helm：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-kubernetes",
  "project": {"id": "java-service"},
  "variables": {
    "IMAGE_REPOSITORY": "ghcr.io/example/java-service",
    "HELM_RELEASE": "java-service",
    "HELM_CHART": "deploy/helm/java-service",
    "KUBE_NAMESPACE": "java-service"
  }
}
```

Java 默认使用 OpenJDK 21。模板值都位于 `shared-library/resources/com/bluersw/jenkins/libraries/v3/`；项目可以覆盖变量、Agent 和同编号阶段。Kubernetes 项目切换 Java 17、21 或 25 时，必须把 `JAVA_VERSION` 和 `MAVEN_IMAGE` 一起改成匹配且固定摘要的镜像；静态 Agent 使用节点上配置的 JDK。默认 Kubernetes Pod 无特权、无 Docker Socket，Registry 配置只挂入 BuildKit，部署令牌只挂入 Helm。

标准 `java-maven-kubernetes` 模板为 Maven 和 Helm 分别挂载独立的 Home `emptyDir`。Maven 的 `.m2` 缓存卷挂载到 `/home/jenkins/.m2`，本地仓库位于 `/home/jenkins/.m2/repository`；Helm 使用另一个 `/home/jenkins`。两个容器以 UID `1000` 运行时都能写各自的 `~/.cache`、`~/.config` 和工具状态目录。默认模板使用 Maven 镜像内置配置，不强制依赖代理专用的 Settings ConfigMap；需要自定义 `settings.xml` 的项目应通过自己的 `agent.yaml` 或 `agent.yamlFile` 明确挂载。

继续使用 Kaniko 时改用兼容模板：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-kubernetes-kaniko",
  "project": {"id": "java-service"},
  "variables": {
    "IMAGE_REPOSITORY": "ghcr.io/example/java-service",
    "HELM_RELEASE": "java-service",
    "HELM_CHART": "deploy/helm/java-service"
  }
}
```

## 容器镜像构建

`containerImage` 的公共字段包括 `context`、`dockerfile`、`destinations`、`buildArgs`、`arguments`、`workDir`、`digestFile`、`digestVariable` 和 `referenceVariable`。BuildKit 还支持：

```json
{
  "type": "containerImage",
  "builder": "buildkit",
  "context": ".",
  "dockerfile": "docker/Dockerfile",
  "destinations": ["ghcr.io/example/app:42", "ghcr.io/example/app:latest"],
  "platforms": ["linux/amd64", "linux/arm64"],
  "target": "runtime",
  "buildArgs": {"VERSION": "42"},
  "cacheFrom": ["type=registry,ref=ghcr.io/example/app:buildcache"],
  "cacheTo": ["type=registry,ref=ghcr.io/example/app:buildcache,mode=max"],
  "arguments": ["--progress=plain"]
}
```

省略 `builder` 时使用 BuildKit。显式设置 `cache: false` 会增加 `--no-cache`，此时不能同时设置 `cacheFrom` 或 `cacheTo`。构建完成后仍会生成纯文本摘要文件、`IMAGE_DIGEST`、`IMAGE_REFERENCE` 和 `context.outputs.image`，不要求部署步骤区分 builder。

BuildKit secret 和 SSH 只填写 Jenkins 绑定后的环境变量名，不填写凭据值，也不要加 `$` 或 `${}`：

```json
{
  "type": "credentials",
  "bindings": [
    {"kind": "string", "credentialsId": "npm-token", "variable": "NPM_TOKEN"},
    {"kind": "sshUserPrivateKey", "credentialsId": "git-key", "keyFileVariable": "GIT_KEY"}
  ],
  "steps": [
    {
      "type": "containerImage",
      "dockerfile": "Dockerfile",
      "destinations": ["ghcr.io/example/app:42"],
      "secrets": [{"id": "npm-token", "envVariable": "NPM_TOKEN"}],
      "ssh": [{"id": "default", "variable": "GIT_KEY"}]
    }
  ]
}
```

`secrets` 每项必须且只能设置 `envVariable` 或 `fileVariable`。secret 临时文件在命令结束时删除，值不会写入 V3 普通变量、构建结果或命令参数。

环境变量 secret 会写入权限为 `0600` 的临时文件；文件凭据和 SSH 凭据只通过临时链接传给 BuildKit。无论构建成功、失败还是收到终止信号，临时目录都会清理。`digestFile`、`metadataFile` 和内部凭据目录必须是 `workDir` 内的相对路径。

## Kubernetes 模板覆盖

默认模板提供固定摘要，但这些值不是强制版本。项目可在 `variables` 中覆盖：

- 镜像：`MAVEN_IMAGE`、`BUILDKIT_IMAGE`、`KANIKO_IMAGE`、`HELM_IMAGE`
- 工具：`BUILDKIT_EXECUTOR`、`BUILDKIT_FRONTEND`、`BUILDKITD_FLAGS`、`KANIKO_EXECUTOR`、`HELM_EXECUTABLE`
- Pod 身份：`POD_RUN_AS_USER`、`POD_RUN_AS_GROUP`、`POD_FS_GROUP`
- Maven/Helm 路径：`MAVEN_USER_HOME`、`MAVEN_CONFIG`、`MAVEN_REPOSITORY`、`HELM_USER_HOME`
- BuildKit/Kaniko 路径和身份：`BUILDKIT_STATE_DIR`、`BUILDKIT_DOCKER_CONFIG`、`BUILDKIT_RUN_AS_USER`、`BUILDKIT_RUN_AS_GROUP`、`KANIKO_DOCKER_CONFIG`
- Registry：`BUILDKIT_REGISTRY_SECRET_NAME`、`KANIKO_SECRET_NAME`、`BUILDKIT_CACHE_REF`
- 资源：`MAVEN_*`、`IMAGE_BUILDER_*`、`HELM_*` 对应的 CPU 和内存 request/limit

默认镜像全部固定摘要，两个 Kubernetes 模板都开放以下四个变量：

| 变量 | 默认值 |
| --- | --- |
| `MAVEN_IMAGE` | `docker.io/library/maven:3.9.11-eclipse-temurin-21@sha256:6fdc855a6ed81d288ca7ca37ac6ff5e9308b612485c0801d70b25a858c83d237` |
| `BUILDKIT_IMAGE` | `docker.io/moby/buildkit:v0.32.2-rootless@sha256:504731e577c20559c00f968f33219f30115e70be29ab96728d1d06e963fc494b` |
| `KANIKO_IMAGE` | `gcr.io/kaniko-project/executor:v1.24.0-debug@sha256:2562c4fe551399514277ffff7dcca9a3b1628c4ea38cb017d7286dc6ea52f4cd` |
| `HELM_IMAGE` | `docker.io/alpine/k8s:1.36.2@sha256:44ef4942e171939b9c665a4a84beb80e2dcdb9a24330d4651cfdfd2e9deecc47` |

其余关键默认值如下：

| 范围 | 默认值 |
| --- | --- |
| Pod 身份 | UID/GID `1000:1000`；`fsGroup` `1000`；`fsGroupChangePolicy` `OnRootMismatch` |
| Maven/Helm | 独立可写 Home `/home/jenkins`；Maven 配置 `/home/jenkins/.m2`；本地仓库 `/home/jenkins/.m2/repository`；默认不依赖 Settings ConfigMap |
| BuildKit | executor `buildctl-daemonless.sh`；frontend `dockerfile.v0`；daemon 参数 `--oci-worker-no-process-sandbox` |
| BuildKit 路径 | state `/home/user/.local/share/buildkit`，同时传给 `buildkitd --root`；Docker config `/home/user/.docker` |
| BuildKit 身份 | UID/GID `1000`；Registry Secret `ghcr-push-config`；缓存 `${IMAGE_REPOSITORY}:buildcache` |
| Kaniko | executor `/kaniko/executor`；Docker config `/kaniko/.docker`；Registry Secret `ghcr-push-config` |
| Helm | executable `helm`；driver `configmap`；ServiceAccount `jenkins-deployer` |
| Maven/BuildKit 资源 | request `250m/512Mi`；limit `2/2Gi` |
| Helm 资源 | request `100m/128Mi`；limit `1/512Mi` |

例如，使用私有镜像仓库和内部工具路径：

```json
{
  "variables": {
    "BUILDKIT_IMAGE": "registry.example.com/ci/buildkit:v0.32.2-rootless@sha256:change-me",
    "BUILDKIT_EXECUTOR": "/opt/buildkit/buildctl-daemonless.sh",
    "BUILDKIT_REGISTRY_SECRET_NAME": "private-registry-config",
    "IMAGE_BUILDER_CPU_LIMIT": "4"
  }
}
```

标准 BuildKit Pod 在 Pod、Maven 和 Helm 层都显式使用数字 UID/GID `1000:1000`，并以 `fsGroup: 1000` 处理 Jenkins Kubernetes 插件最终注入的 workspace `emptyDir` 和其他共享卷。Maven 同时设置 `HOME`、`MAVEN_CONFIG`、Java `user.home` 和本地仓库路径；Maven 与 Helm 分别挂载自己的可写 Home，避免非 root 进程回退到 `/root/.m2` 或因镜像内 Home 父目录不可写而失败。如果存储驱动不支持 `fsGroup`，必须在集群存储层提供等价的组写权限，不能通过关闭 `runAsNonRoot` 绕过。

Jenkins Kubernetes plugin 会在合并 Pipeline YAML 后自动注入 `jnlp`，所以共享模板不直接声明该容器。`restrictedPssSecurityContext` 会补齐 `runAsNonRoot`、禁止提权、RuntimeDefault seccomp 和 drop ALL，但不会补数字 UID/GID；自动注入且没有容器级身份覆盖的 `jnlp` 会继承本模板 Pod 级的 `runAsUser/runAsGroup`。Chart 5.9.49 的 `agent.runAsUser/runAsGroup` 只作用于 Chart 自带默认 PodTemplate 的 `jnlp`，Pipeline 的 `podTemplate(yaml: ...)` 不会可靠继承它们，因此 Chart values 只能作为默认 Agent 的兼容设置，不能代替项目或共享模板中的 Pod 级数字身份。使用 `agent.yaml` 或 `agent.yamlFile` 完全覆盖标准模板的项目，也必须在自己的 YAML 中提供相同合同。

BuildKit 容器继续以独立的 `BUILDKIT_RUN_AS_USER/BUILDKIT_RUN_AS_GROUP` 运行，Pod 要求 Kubernetes 1.30+，并使用官方 rootless 方案要求的 `Unconfined` seccomp/AppArmor 和 `--oci-worker-no-process-sandbox`。RootlessKit 启动时还要通过镜像内的 `newuidmap/newgidmap` 建立从容器 UID/GID `1000` 到 subordinate ID 范围的映射。Jenkins 的 `restrictedPssSecurityContext` 默认设置 `allowPrivilegeEscalation: false` 和 `drop: ALL`，会让这两个帮助程序报 `operation not permitted`。因此标准 BuildKit 容器显式设置 `allowPrivilegeEscalation: true`，在先 drop ALL 后只加回 `SETUID`、`SETGID`；这不是 `privileged: true`，也不会给 Maven、Helm 或 `jnlp` 相同权限。节点还必须允许非特权用户命名空间。Kaniko 兼容模板保留其现有镜像用户合同。多平台参数只声明目标平台；执行非本机架构的 `RUN` 仍要求节点预先安装 binfmt/QEMU，默认模板不会申请特权来安装。

私有 Registry 应创建类型为 `kubernetes.io/dockerconfigjson`、键为 `.dockerconfigjson` 的 Secret，并用 `BUILDKIT_REGISTRY_SECRET_NAME` 或 `KANIKO_SECRET_NAME` 引用。Secret 只挂入对应镜像构建容器，不会挂入 Maven 或 Helm；Helm 继续使用短期投射的 ServiceAccount token。

版本升级时同时更新可读标签和摘要，先验证 rootless 启动、Registry 推送、缓存导入导出和摘要输出，再提交配置变更。不要把默认值改成 `latest`。如果集群安全策略、镜像布局或挂载方式差异较大，使用 `agent.yaml` 或 `agent.yamlFile` 提供完整 Pod；无特权、禁止 Docker Socket、禁止 hostPath 等校验仍会执行。

## 多项目

项目参数只传编号，不传文件路径：

```json
{
  "schemaVersion": 3,
  "variables": {},
  "agent": {"type": "static", "label": "linux"},
  "stages": [{"id": "build", "name": "Build", "steps": [{"type": "command", "script": "true"}]}],
  "projects": {
    "execution": "parallel",
    "maxParallel": 2,
    "selectionParameter": "PROJECTS",
    "items": [
      {"id": "api", "configFiles": ["services/api/ci/jenkins-project.json"]},
      {"id": "worker", "configFiles": ["services/worker/ci/jenkins-project.json"]}
    ]
  }
}
```

普通 Jenkins 字符串参数使用逗号分隔编号。`multiChoice` 参数设置 `provider: "customCheckbox"` 时才调用 Custom Checkbox Parameter；未设置时仍是普通字符串参数，因此该插件不是 V3 运行依赖。项目清单可来自本地文件、共享类库资源或已加入 `trustedHosts` 的 HTTPS JSON。

## V2 转换

```bash
python3 scripts/convert_v2_to_v3.py \
  old/jenkins-project.json \
  --output-dir converted \
  --report converted/report.json
```

转换成功返回 `0`。V3.2.0 可转换单一 npm、Gradle、MSBuild、Xcode 动作，以及 Jest/LCOV、OpenCover 和带 xcresult 路径的 LLVM 覆盖率。包含管道、多个 Xcode 动作、现代 `dotnet` 命令或无法确定 xcresult 的配置返回 `2`，只写明确的人工处理报告，不写不可靠的 V3 配置，也不修改 V2 文件。检测到旧 BuildKit、Kaniko 或 Helm 命令时，报告会建议改用标准步骤。

## Jenkins 平台

`jenkins-platform/` 提供 Jenkins `2.568.2`、Chart `5.9.49`、Java 25 Controller/Agent、固定插件、JCasC、WebSocket 动态 Pod、持久化和权限拆分示例。V3.2.0 新增固定插件为 HTTP Request、SSH Build Agents、Agent Server Parameter、Custom Checkbox Parameter 和 Coverage。生产升级前必须完成 Jenkins Home 备份和隔离恢复演练。

Kubernetes 模板通过 `POD_HTTP_PROXY`、`POD_HTTPS_PROXY` 和 `POD_NO_PROXY` 配置出站代理，默认均为空。配置后会同时注入固定摘要的 `jnlp` 容器和语言容器，并提供大写、兼容小写两组标准环境变量。需要沿用 Controller 代理时，可在项目变量中分别设置为 `${HTTP_PROXY}`、`${HTTPS_PROXY}` 和 `${NO_PROXY}`，并通过 Jenkins 全局环境变量、Folder 属性或 `withEnv` 将对应值提供给 Pipeline。
