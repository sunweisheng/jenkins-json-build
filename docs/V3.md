# Jenkins Json Build V3

V3 的核心是通用阶段和步骤注册机制。Java 是 `v3.0.0` 第一个完整实现的技术栈；以后增加 Node、.NET 或移动端时，不需要修改 JSON 读取、Agent、多项目和回调代码。

## 支持范围

正式步骤：

- `command`、`condition`、`retry`、`timeout`、`setVariable`
- `credentials`、`archive`
- `maven`、`junit`、`jacoco`、`sonarqube`
- `containerImage`，默认 builder 为 `buildkit`，兼容 `kaniko`
- `helm`，支持 `lint`、`template`、`upgrade`、`status`、`rollback`

V3.0 不提供 Jest、LLVM、MSBuild、Xcode、Android Gradle 和 React Native 专用步骤。V2 项目可继续使用 `v2.1`，也可先运行转换工具生成报告。

## 配置入口

```groovy
@Library('jenkins-json-build@v3.1.0') _

jenkinsJsonBuild(
    configFiles: ['ci/base.json', 'ci/service.json'],
    onlyStages: ['test', 'package'],
    projectIds: ['api'],
    callbacks: [
        success: { context, error -> echo "${context.projectId} success" },
        failure: { context, error -> echo "${context.projectId} failed" }
    ],
    stepHandlers: [
        'company.customStep': { context, config ->
            echo config.message
        }
    ]
)
```

每次调用都会创建新的执行对象。不同 Jenkins 构建和不同项目不共享当前阶段、变量或结果。
`configFiles` 会按填写顺序合并为一份配置，后面的变量和普通字段覆盖前面的值，同编号阶段在原位置合并。

## JSON 结构

```json
{
  "schemaVersion": 3,
  "project": {"id": "example"},
  "variables": {"JAVA_VERSION": "21"},
  "runtimeVariables": [
    {"name": "SHORT_SHA", "source": "command", "script": "git rev-parse --short=12 HEAD"}
  ],
  "parameters": [
    {"name": "DEPLOY", "type": "boolean", "defaultValue": false}
  ],
  "agent": {"type": "static", "label": "linux"},
  "stages": [
    {
      "id": "test",
      "name": "Test",
      "timeoutMinutes": 30,
      "retries": 1,
      "condition": {"variable": "DEPLOY", "operator": "equals", "value": true},
      "variables": {},
      "steps": [
        {"type": "maven", "goals": ["clean", "test"]},
        {"type": "junit", "testResults": "**/target/surefire-reports/TEST-*.xml"}
      ]
    }
  ],
  "post": {
    "success": [],
    "failure": [],
    "cancelled": [],
    "always": []
  }
}
```

变量从低到高依次为 Jenkins 环境和参数、全局变量、运行时变量、项目变量、阶段变量、步骤变量。后面的同名变量覆盖前面的值。未解析的 `${NAME}` 会直接停止构建。

运行时变量支持 `env`、`parameter`、`command`、`file`、`http` 和 `json`。HTTP 地址必须是 HTTPS，主机必须放入 `trustedHosts`。Credentials 只能通过 `credentials` 步骤临时绑定；凭据值不会进入普通变量和构建结果。命令内直接使用 Jenkins 绑定的 `$PASSWORD` 一类 shell 环境变量，不要写成 V3 的 `${PASSWORD}`。

## Java 模板

静态 Agent：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-static",
  "project": {"id": "java-service"},
  "variables": {"ENABLE_SONAR": false}
}
```

Kubernetes + rootless BuildKit + Helm：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-kubernetes",
  "project": {"id": "java-service"},
  "variables": {
    "IMAGE_REPOSITORY": "ghcr.io/example/java-service",
    "HELM_RELEASE": "java-service",
    "HELM_CHART": "deploy/helm/java-service",
    "KUBE_NAMESPACE": "java-service"
  }
}
```

Java 默认使用 OpenJDK 21。模板值都位于 `shared-library/resources/com/bluersw/jenkins/libraries/v3/`；项目可以覆盖变量、Agent 和同编号阶段。Kubernetes 项目切换 Java 17、21 或 25 时，必须把 `JAVA_VERSION` 和 `MAVEN_IMAGE` 一起改成匹配且固定摘要的镜像；静态 Agent 使用节点上配置的 JDK。默认 Kubernetes Pod 无特权、无 Docker Socket，Registry 配置只挂入 BuildKit，部署令牌只挂入 Helm。

继续使用 Kaniko 时改用兼容模板：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-kubernetes-kaniko",
  "project": {"id": "java-service"},
  "variables": {
    "IMAGE_REPOSITORY": "ghcr.io/example/java-service",
    "HELM_RELEASE": "java-service",
    "HELM_CHART": "deploy/helm/java-service"
  }
}
```

## 容器镜像构建

`containerImage` 的公共字段包括 `context`、`dockerfile`、`destinations`、`buildArgs`、`arguments`、`workDir`、`digestFile`、`digestVariable` 和 `referenceVariable`。BuildKit 还支持：

```json
{
  "type": "containerImage",
  "builder": "buildkit",
  "context": ".",
  "dockerfile": "docker/Dockerfile",
  "destinations": ["ghcr.io/example/app:42", "ghcr.io/example/app:latest"],
  "platforms": ["linux/amd64", "linux/arm64"],
  "target": "runtime",
  "buildArgs": {"VERSION": "42"},
  "cacheFrom": ["type=registry,ref=ghcr.io/example/app:buildcache"],
  "cacheTo": ["type=registry,ref=ghcr.io/example/app:buildcache,mode=max"],
  "arguments": ["--progress=plain"]
}
```

省略 `builder` 时使用 BuildKit。显式设置 `cache: false` 会增加 `--no-cache`，此时不能同时设置 `cacheFrom` 或 `cacheTo`。构建完成后仍会生成纯文本摘要文件、`IMAGE_DIGEST`、`IMAGE_REFERENCE` 和 `context.outputs.image`，不要求部署步骤区分 builder。

BuildKit secret 和 SSH 只填写 Jenkins 绑定后的环境变量名，不填写凭据值，也不要加 `$` 或 `${}`：

```json
{
  "type": "credentials",
  "bindings": [
    {"kind": "string", "credentialsId": "npm-token", "variable": "NPM_TOKEN"},
    {"kind": "sshUserPrivateKey", "credentialsId": "git-key", "keyFileVariable": "GIT_KEY"}
  ],
  "steps": [
    {
      "type": "containerImage",
      "dockerfile": "Dockerfile",
      "destinations": ["ghcr.io/example/app:42"],
      "secrets": [{"id": "npm-token", "envVariable": "NPM_TOKEN"}],
      "ssh": [{"id": "default", "variable": "GIT_KEY"}]
    }
  ]
}
```

`secrets` 每项必须且只能设置 `envVariable` 或 `fileVariable`。secret 临时文件在命令结束时删除，值不会写入 V3 普通变量、构建结果或命令参数。

环境变量 secret 会写入权限为 `0600` 的临时文件；文件凭据和 SSH 凭据只通过临时链接传给 BuildKit。无论构建成功、失败还是收到终止信号，临时目录都会清理。`digestFile`、`metadataFile` 和内部凭据目录必须是 `workDir` 内的相对路径。

## Kubernetes 模板覆盖

默认模板提供固定摘要，但这些值不是强制版本。项目可在 `variables` 中覆盖：

- 镜像：`MAVEN_IMAGE`、`BUILDKIT_IMAGE`、`KANIKO_IMAGE`、`HELM_IMAGE`
- 工具：`BUILDKIT_EXECUTOR`、`BUILDKIT_FRONTEND`、`BUILDKITD_FLAGS`、`KANIKO_EXECUTOR`、`HELM_EXECUTABLE`
- 路径和身份：`BUILDKIT_STATE_DIR`、`BUILDKIT_DOCKER_CONFIG`、`BUILDKIT_RUN_AS_USER`、`BUILDKIT_RUN_AS_GROUP`、`KANIKO_DOCKER_CONFIG`
- Registry：`BUILDKIT_REGISTRY_SECRET_NAME`、`KANIKO_SECRET_NAME`、`BUILDKIT_CACHE_REF`
- 资源：`MAVEN_*`、`IMAGE_BUILDER_*`、`HELM_*` 对应的 CPU 和内存 request/limit

默认镜像全部固定摘要，两个 Kubernetes 模板都开放以下四个变量：

| 变量 | 默认值 |
| --- | --- |
| `MAVEN_IMAGE` | `docker.io/library/maven:3.9.11-eclipse-temurin-21@sha256:6fdc855a6ed81d288ca7ca37ac6ff5e9308b612485c0801d70b25a858c83d237` |
| `BUILDKIT_IMAGE` | `docker.io/moby/buildkit:v0.32.2-rootless@sha256:504731e577c20559c00f968f33219f30115e70be29ab96728d1d06e963fc494b` |
| `KANIKO_IMAGE` | `gcr.io/kaniko-project/executor:v1.24.0-debug@sha256:2562c4fe551399514277ffff7dcca9a3b1628c4ea38cb017d7286dc6ea52f4cd` |
| `HELM_IMAGE` | `docker.io/alpine/k8s:1.36.2@sha256:44ef4942e171939b9c665a4a84beb80e2dcdb9a24330d4651cfdfd2e9deecc47` |

其余关键默认值如下：

| 范围 | 默认值 |
| --- | --- |
| BuildKit | executor `buildctl-daemonless.sh`；frontend `dockerfile.v0`；daemon 参数 `--oci-worker-no-process-sandbox` |
| BuildKit 路径 | state `/home/user/.local/share/buildkit`，同时传给 `buildkitd --root`；Docker config `/home/user/.docker` |
| BuildKit 身份 | UID/GID `1000`；Registry Secret `ghcr-push-config`；缓存 `${IMAGE_REPOSITORY}:buildcache` |
| Kaniko | executor `/kaniko/executor`；Docker config `/kaniko/.docker`；Registry Secret `ghcr-push-config` |
| Helm | executable `helm`；driver `configmap`；ServiceAccount `jenkins-deployer` |
| Maven/BuildKit 资源 | request `250m/512Mi`；limit `2/2Gi` |
| Helm 资源 | request `100m/128Mi`；limit `1/512Mi` |

例如，使用私有镜像仓库和内部工具路径：

```json
{
  "variables": {
    "BUILDKIT_IMAGE": "registry.example.com/ci/buildkit:v0.32.2-rootless@sha256:change-me",
    "BUILDKIT_EXECUTOR": "/opt/buildkit/buildctl-daemonless.sh",
    "BUILDKIT_REGISTRY_SECRET_NAME": "private-registry-config",
    "IMAGE_BUILDER_CPU_LIMIT": "4"
  }
}
```

默认 BuildKit 容器固定以非 root UID/GID 运行，Pod 要求 Kubernetes 1.30+，并使用官方 rootless 方案要求的 `Unconfined` seccomp/AppArmor 和 `--oci-worker-no-process-sandbox`。节点还必须允许非特权用户命名空间。Maven、Kaniko 和 Helm 容器按各自官方镜像用户运行，但禁止提权并移除全部 capabilities。多平台参数只声明目标平台；执行非本机架构的 `RUN` 仍要求节点预先安装 binfmt/QEMU，默认模板不会申请特权来安装。

私有 Registry 应创建类型为 `kubernetes.io/dockerconfigjson`、键为 `.dockerconfigjson` 的 Secret，并用 `BUILDKIT_REGISTRY_SECRET_NAME` 或 `KANIKO_SECRET_NAME` 引用。Secret 只挂入对应镜像构建容器，不会挂入 Maven 或 Helm；Helm 继续使用短期投射的 ServiceAccount token。

版本升级时同时更新可读标签和摘要，先验证 rootless 启动、Registry 推送、缓存导入导出和摘要输出，再提交配置变更。不要把默认值改成 `latest`。如果集群安全策略、镜像布局或挂载方式差异较大，使用 `agent.yaml` 或 `agent.yamlFile` 提供完整 Pod；无特权、禁止 Docker Socket、禁止 hostPath 等校验仍会执行。

## 多项目

项目参数只传编号，不传文件路径：

```json
{
  "schemaVersion": 3,
  "variables": {},
  "agent": {"type": "static", "label": "linux"},
  "stages": [{"id": "build", "name": "Build", "steps": [{"type": "command", "script": "true"}]}],
  "projects": {
    "execution": "parallel",
    "maxParallel": 2,
    "selectionParameter": "PROJECTS",
    "items": [
      {"id": "api", "configFiles": ["services/api/ci/jenkins-project.json"]},
      {"id": "worker", "configFiles": ["services/worker/ci/jenkins-project.json"]}
    ]
  }
}
```

普通 Jenkins 字符串参数使用逗号分隔编号。`multiChoice` 参数设置 `provider: "customCheckbox"` 时才调用 Custom Checkbox Parameter；未设置时仍是普通字符串参数，因此该插件不是 V3 运行依赖。项目清单可来自本地文件、共享类库资源或已加入 `trustedHosts` 的 HTTPS JSON。

## V2 转换

```bash
python3 scripts/convert_v2_to_v3.py \
  old/jenkins-project.json \
  --output-dir converted \
  --report converted/report.json
```

转换成功返回 `0`。遇到 Node、.NET、Android、iOS、React Native、Jest、LLVM、MSBuild 等未实现类型或对应命令时返回 `2`，只写人工处理报告，不写 V3 配置，也不修改 V2 文件。检测到旧 BuildKit、Kaniko 或 Helm 命令时，报告会建议改用标准步骤。
