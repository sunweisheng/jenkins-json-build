# Jenkins Json Build V3

V3 的核心是通用阶段和步骤注册机制。Java 是 `v3.0.0` 第一个完整实现的技术栈；以后增加 Node、.NET 或移动端时，不需要修改 JSON 读取、Agent、多项目和回调代码。

## 支持范围

正式步骤：

- `command`、`condition`、`retry`、`timeout`、`setVariable`
- `credentials`、`archive`
- `maven`、`junit`、`jacoco`、`sonarqube`
- `containerImage`，当前 builder 为 `kaniko`
- `helm`，支持 `lint`、`template`、`upgrade`、`status`、`rollback`

V3.0 不提供 Jest、LLVM、MSBuild、Xcode、Android Gradle 和 React Native 专用步骤。V2 项目可继续使用 `v2.1`，也可先运行转换工具生成报告。

## 配置入口

```groovy
@Library('jenkins-json-build@v3.0.0') _

jenkinsJsonBuild(
    configFiles: ['ci/base.json', 'ci/service.json'],
    onlyStages: ['test', 'package'],
    projectIds: ['api'],
    callbacks: [
        success: { context, error -> echo "${context.projectId} success" },
        failure: { context, error -> echo "${context.projectId} failed" }
    ],
    stepHandlers: [
        'company.customStep': { context, config ->
            echo config.message
        }
    ]
)
```

每次调用都会创建新的执行对象。不同 Jenkins 构建和不同项目不共享当前阶段、变量或结果。
`configFiles` 会按填写顺序合并为一份配置，后面的变量和普通字段覆盖前面的值，同编号阶段在原位置合并。

## JSON 结构

```json
{
  "schemaVersion": 3,
  "project": {"id": "example"},
  "variables": {"JAVA_VERSION": "21"},
  "runtimeVariables": [
    {"name": "SHORT_SHA", "source": "command", "script": "git rev-parse --short=12 HEAD"}
  ],
  "parameters": [
    {"name": "DEPLOY", "type": "boolean", "defaultValue": false}
  ],
  "agent": {"type": "static", "label": "linux"},
  "stages": [
    {
      "id": "test",
      "name": "Test",
      "timeoutMinutes": 30,
      "retries": 1,
      "condition": {"variable": "DEPLOY", "operator": "equals", "value": true},
      "variables": {},
      "steps": [
        {"type": "maven", "goals": ["clean", "test"]},
        {"type": "junit", "testResults": "**/target/surefire-reports/TEST-*.xml"}
      ]
    }
  ],
  "post": {
    "success": [],
    "failure": [],
    "cancelled": [],
    "always": []
  }
}
```

变量从低到高依次为 Jenkins 环境和参数、全局变量、运行时变量、项目变量、阶段变量、步骤变量。后面的同名变量覆盖前面的值。未解析的 `${NAME}` 会直接停止构建。

运行时变量支持 `env`、`parameter`、`command`、`file`、`http` 和 `json`。HTTP 地址必须是 HTTPS，主机必须放入 `trustedHosts`。Credentials 只能通过 `credentials` 步骤临时绑定；凭据值不会进入普通变量和构建结果。命令内直接使用 Jenkins 绑定的 `$PASSWORD` 一类 shell 环境变量，不要写成 V3 的 `${PASSWORD}`。

## Java 模板

静态 Agent：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-static",
  "project": {"id": "java-service"},
  "variables": {"ENABLE_SONAR": false}
}
```

Kubernetes + Kaniko + Helm：

```json
{
  "schemaVersion": 3,
  "extends": "java-maven-kubernetes",
  "project": {"id": "java-service"},
  "variables": {
    "IMAGE_REPOSITORY": "ghcr.io/example/java-service",
    "HELM_RELEASE": "java-service",
    "HELM_CHART": "deploy/helm/java-service",
    "KUBE_NAMESPACE": "java-service"
  }
}
```

Java 默认使用 OpenJDK 21。模板值都位于 `shared-library/resources/com/bluersw/jenkins/libraries/v3/`；项目可以覆盖变量、Agent 和同编号阶段。Kubernetes 项目切换 Java 17、21 或 25 时，必须把 `JAVA_VERSION` 和 `MAVEN_IMAGE` 一起改成匹配且固定摘要的镜像；静态 Agent 使用节点上配置的 JDK。默认 Kubernetes Pod 无特权、无 Docker Socket，GHCR 配置只挂入 Kaniko，部署令牌只挂入 Helm。

## 多项目

项目参数只传编号，不传文件路径：

```json
{
  "schemaVersion": 3,
  "variables": {},
  "agent": {"type": "static", "label": "linux"},
  "stages": [{"id": "build", "name": "Build", "steps": [{"type": "command", "script": "true"}]}],
  "projects": {
    "execution": "parallel",
    "maxParallel": 2,
    "selectionParameter": "PROJECTS",
    "items": [
      {"id": "api", "configFiles": ["services/api/ci/jenkins-project.json"]},
      {"id": "worker", "configFiles": ["services/worker/ci/jenkins-project.json"]}
    ]
  }
}
```

普通 Jenkins 字符串参数使用逗号分隔编号。`multiChoice` 参数设置 `provider: "customCheckbox"` 时才调用 Custom Checkbox Parameter；未设置时仍是普通字符串参数，因此该插件不是 V3 运行依赖。项目清单可来自本地文件、共享类库资源或已加入 `trustedHosts` 的 HTTPS JSON。

## V2 转换

```bash
python3 scripts/convert_v2_to_v3.py \
  old/jenkins-project.json \
  --output-dir converted \
  --report converted/report.json
```

转换成功返回 `0`。遇到 Node、.NET、Android、iOS、React Native、Jest、LLVM、MSBuild 等未实现类型或对应命令时返回 `2`，只写人工处理报告，不写 V3 配置，也不修改 V2 文件。检测到旧 Kaniko 或 Helm 命令时，报告会建议改用标准步骤。

## Jenkins 平台

`jenkins-platform/` 提供 Jenkins `2.568.2`、Chart `5.9.49`、Java 25 Controller/Agent、固定插件、JCasC、WebSocket 动态 Pod、持久化和权限拆分示例。生产升级前必须完成 Jenkins Home 备份和隔离恢复演练。
